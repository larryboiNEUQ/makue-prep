约 5 分钟

单元 1 数步数：n 是什么

1.1 导入

先别管符号。

审查时要回答：列表长度叫 n 时，这段代码大约执行多少次「比一下 / 看一眼」？

n 变大，步数怎么涨，才决定会不会卡。

1.2 去读

打开 Open Data Structures（Java 版）§1.3.3 Asymptotic Notation。

重点：用「计算机指令次数」谈运行时间；为何用 big-Oh 做粗粒度描述。

opendatastructures.org · §1.3.3 Asymptotic Notation 读到文中 snippet() 那个单层 for 示例即可。不必抠证明。

1.3 讲解

口语义如下：

写法白话典型样子
O(1) 和 n 几乎无关 arr[i]；Set/Map 按键查（平均）
O(n) 和长度成正比 一层 for；arr.includes(x) 最坏
O(n²) 和长度的平方成正比 两层都扫 n；或外层 n 次、每次再 includes 整表
具体数字

n = 10 → 单层约 10 步，双层约 100 步。

n = 1000 → 单层约 1000，双层约 100 万。差别会突然变痛。

审查话术示例：「这里对 length=n 的列表做了嵌套扫描，是 O(n²)。n 到几千时可能卡。」

这句话比只丢一个符号更有用。

1.4 小练

下面函数里，内层比较 === 大约执行多少次？（设 list.length === n）

把注释里的 ??? 改成 n、n*n 或 1。再补上粗粒度复杂度注释。

参考答案
function countPairs(list) {
  let hits = 0;
  for (let i = 0; i < list.length; i++) {
    for (let j = 0; j < list.length; j++) {
      if (list[i] === list[j]) hits++; // 约 n*n 次
    }
  }
  return hits;
}
// 粗粒度复杂度：O(n*n) 或 O(n²)

约 6 分钟

单元 2 嵌套循环与隐藏的 n²

2.1 导入

不一定写成双 for 才叫 O(n²)。

外层扫一遍，里面每次又 includes / find 整表，效果一样贵。

本单元目标：认出隐藏嵌套，并改成 Set。

2.2 去读

打开 javascript.info《Loops: while and for》的 Labels for break/continue 小节。

开头用「多层嵌套循环」作例子。弄清：内层会相对外层再跑一整圈。

javascript.info · Labels for break/continue 读懂「外层 × 内层」即可。标签语法不是本课重点。

2.3 讲解

// 隐藏的 n²：外层 n 次，每次 includes 再扫 n
for (const id of incomingIds) {
  if (existingIds.includes(id)) { /* ... */ }
}

若两边长度都接近 n，总步数约 n²。

改法：先花 O(n) 建 Set。再每次 has（平均约 O(1)）。总体约 O(n)。

审查口令：热路径上对数组 includes；列表会变长时，先 new Set，再 has。

2.4 小练

实现 filterAllowed(incoming, allowed)：返回 incoming 里出现在 allowed 中的元素（保持原顺序）。

禁止在循环里对数组用 includes。请用 Set。

参考答案
function filterAllowed(incoming, allowed) {
  const allowedSet = new Set(allowed);
  const result = [];
  for (const id of incoming) {
    if (allowedSet.has(id)) result.push(id);
  }
  return result;
}

约 5 分钟

单元 3 数组：便宜什么、贵什么

3.1 导入

数组擅长按位置读写。

数组不擅长反复按内容查找。

先分清哪一类操作便宜，审查才不会乱优化。

3.2 去读

打开 MDN Array.prototype.includes() 的 Description。

看它如何从左往右搜，以及「读 length 再逐个访问」的行为。

MDN · Array.prototype.includes · Description 扫一眼同页语法参数即可。记住「查找 ≈ 线性扫」就够。

3.3 讲解

操作直觉代价说明
读/写下标 arr[i] O(1) 知道位置就很快
末尾 push / pop 摊还 O(1) 通常很便宜
遍历一遍 O(n) 必然看每个元素
includes / indexOf / find O(n) 最坏从左扫到右
循环里反复 includes 易变 O(n²) 审查红灯区

3.4 小练

给下面三行各标上复杂度。把注释里的 ? 改成 O(1)、O(n) 或 O(n*n)（也可用 O(n²)）。

参考答案
const arr = [/* n 个元素 */];
arr[0];                        // O(1)
arr.includes(x);               // O(n)
for (const a of arr) {
  arr.includes(a);             // O(n*n) 或 O(n²)
}

约 7 分钟

单元 4 Set：专门回答「有没有」

4.1 导入

Set 存唯一值。

平均情况下，has 比同规模数组的 includes 便宜。

适合「这个值在不在集合里」问很多遍。

4.2 去读

打开 MDN Set 页面，依次读两处：

1) Description 唯一值、插入序、以及规范对平均访问时间的要求。 2) Performance has 平均快于同长度数组的 includes。

4.3 讲解

const existing = new Set(["a", "b", "c"]);
existing.has("b");  // true
existing.add("d");

需要顺序、下标或重复元素时，继续用数组。

建 Set 本身是 O(n)。只查 1 次时，单次 includes 未必更差。

查很多次时，Set 才凸显。

4.4 小练

实现 hasDuplicate(nums)：数组里有重复元素则返回 true，否则返回 false。

用 Set。目标平均接近 O(n)。不要双重循环。

参考答案
function hasDuplicate(nums) {
  const seen = new Set();
  for (const x of nums) {
    if (seen.has(x)) return true;
    seen.add(x);
  }
  return false;
}
// 也可：return new Set(nums).size !== nums.length;

约 6 分钟

单元 5 Map：专门回答「这个键对应谁」

5.1 导入

Set 只答「在不在」。

若要「用 id 拿到整行对象」，用 Map（或 id 为键的普通对象）。

反复 arr.find(u => u.id === id) 是 O(n)。

5.2 去读

打开 javascript.info《Map and Set》的 Map 小节。

看 set、get、has，以及和普通对象的差别直觉。

javascript.info · Map 可选加深：同页旁链 MDN Map · Description。

5.3 讲解

const byId = new Map(users.map(u => [u.id, u]));
byId.get("u2");  // 之后每次查找都便宜
和普通对象 {}

键几乎总是字符串/数字时，对象字面量也常够用。

Map 更适合任意类型键，或频繁增删且要保持插入序。

审查里两者都能表达「按 id 索引」。

5.4 小练

实现 indexById(users)：返回一个 Map，键为 user.id，值为整个 user 对象。

再实现 getName(byId, id)：用 Map 取名字；找不到返回 null。

参考答案
function indexById(users) {
  return new Map(users.map(u => [u.id, u]));
}

function getName(byId, id) {
  const u = byId.get(id);
  return u ? u.name : null;
}

约 6 分钟

单元 6 取舍表 + 一条审查评论

6.1 导入

工具没有绝对好坏。

看三件事：你要做什么、查几次、n 多大。

最后练写一条能落地的审查评论。

6.2 去读

打开 javascript.info《Map and Set》的 Summary。

对照「何时用 Map / Set」。

javascript.info · Summary 可选：MDN Set · Relation to arrays。

6.3 讲解

你想做的事优先考虑别一上来就…
保持顺序、按位置读写、允许重复 数组 强行 Set 丢掉重复与下标
很多次「值在不在」 Set 循环里 arr.includes
很多次「用 id 取整行」 Map / id 索引对象 每次 arr.find
只扫一次做过滤/映射 数组 filter / map 为一次遍历引入复杂结构
两份列表求交集、查重 先把一侧放进 Set 双重 for 硬比
经验法则：「只处理一次」→ 数组往往够。「同样的查找会做很多次」→ 先建 Set/Map。

6.4 小练（审查评论）

假设 PR 里有这段代码（incoming 与 existing 都可能到几千）： 

for (const id of incoming) {
  if (existing.includes(id)) mark(id);
}

在框里写一条简短审查评论（中文或英文都行）。应提到：问题（复杂度/热路径）、建议（Set）、以及何时值得改。

示例评论
这里对 existing 反复 includes，两边都接近 n 时是 O(n²)。
若这是热路径且列表会变长，建议先 const set = new Set(existing)，
再 set.has(id)。若整个程序只查一次、n 很小，可先保持可读性。
