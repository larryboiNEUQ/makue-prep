第 01 节

计算机在干什么

程序是一份按顺序执行的指令清单。电脑几乎总是从上到下、一步一步做（除非你故意跳转）。

三件事反复出现：

  • 输入——给你的数据（用户点了按钮、读到一个列表）。
  • 处理——按规则改写、判断、计算。
  • 输出——结果（屏幕显示、返回一个值、写入文件）。
比喻
像做菜：菜谱是程序，食材是输入，炒完盛盘是输出。漏一步或顺序错了，结果就变。
记住：读代码时先问「这一行在改什么？下一步去哪？」——比先背名词有用。
第 02 节

变量与值

变量是贴了名字的箱子。箱子里放着一个值（数字、文字、真假等）。

let name = "小李";  // 箱子叫 name，里面是文字
let count = 3;       // 箱子叫 count，里面是数字 3
count = 4;            // 把箱子里的东西换成 4
  • 名字方便你引用「那个东西」，不用每次重写具体内容。
  • 赋值 = 的意思是「把右边放进左边的箱子」，不是数学里的「相等」。
对比：const 是「这个箱子不许换内容」；let 允许之后再换。读码时看到 const，可假定它不会被重新赋值。
第 03 节

函数：把步骤打包

函数把「一串步骤」起个名字。调用时：传入参数（原料），得到返回值（成品）。

function double(n) {
  return n * 2;   // 把结果交回去
}
let x = double(5);  // x 变成 10
  • 参数：调用时塞进去的值（上面的 5）。
  • 返回值：函数算完交给外面的东西（上面的 10）。
  • 没有 return 时，外面常常拿到「空」（undefined）——调用方别指望有结果。
比喻
函数像榨汁机：水果进（参数），果汁出（返回值）。机器名字是函数名。
第 04 节

条件与循环

if：按情况走不同路

if (score >= 60) {
  // 及格时做这些
} else {
  // 否则做这些
}

for：把同一件事做多遍

「扫一遍」= 按顺序看列表里的每一个元素，通常各看一次。

for (let i = 0; i < list.length; i++) {
  // 对 list[i] 做点事
}
口语：一层循环 ≈ 「把清单从头到尾过一遍」。两层循环套在一起 ≈ 「对外面每一个，里面再完整扫一遍」——次数会乘起来。正式课会细讲。
第 05 节

数组：一排有编号的格子

数组是有序的一排值。每个位置有下标（从 0 起算）。长度是格子个数。

const fruits = ["苹果", "香蕉", "梨"];
// 下标:        0        1       2
// fruits.length === 3
// fruits[1] === "香蕉"

常见动作：用下标取值、看长度、从头扫到尾。正式课会问：扫一遍要花多少「步」？

第 06 节

读码级 JS / TS（够用就好）

下面只要求能读懂，不要求默写全部语法。

const / let

const 绑定后不重新赋值；let 可以改。现代代码里优先 const。

简单函数

const add = (a, b) => a + b;  // 箭头函数，返回 a+b

.includes / .filter

const nums = [1, 2, 3];
nums.includes(2);           // true：里面有没有 2？（会扫）
nums.filter(n => n > 1);   // [2, 3]：留下符合条件的

Set / Map（各一句话）

  • Set：一堆不重复的值，适合问「有没有这个？」（正式课对比数组 includes）。
  • Map：一堆键 → 值，适合问「这个 id 对应谁？」。

类型形状 { id: string }

在 TypeScript 里，这只是在说：「这个对象长这样——有一个叫 id 的字段，类型是字符串」。先当外形说明，不必深挖类型系统。

// 形状：至少有一个字符串 id
type User = { id: string };
const u: User = { id: "u1" };
第 07 节

复杂度直觉（还不用背表）

n = 问题规模，常指「列表有多长」。列表越长，某些做法越慢。

为何「数组上反复 includes」贵？

每次 includes 都可能把数组扫一遍。若外层再对 n 个元素各做一次 includes， 就变成「扫了大约 n 遍」——数据一大就明显慢。更好的结构（如 Set）把「有没有」变得便宜——这是正式课的核心。

垫课目标：听到「O(n) / O(n²)」时，能联想到「扫一遍 / 扫成方阵」，而不必先背完整符号表。
